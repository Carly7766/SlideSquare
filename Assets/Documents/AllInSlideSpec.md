# 一斉スライド 仕様書

「ダイナミックな動き」「形勢逆転・一発逆転」を補うための新規アクション「一斉スライド」の仕様。検討経緯（他の候補案との比較）はチャットログに譲り、ここでは採用した仕様のみを定義する。ルールそのものの正は本書とし、`GameDesign.md`にも要約を反映する。

## 1. 狙い

`DesignRationale.md`が繰り返し警戒しているのは「膠着」「レースへの縮退」であり、既存の調整ルール（定着・移動連動スライド・巻き戻し禁止・千日手）はすべて**必ず決着がつくこと**を優先して設計されている。そのため、劣勢側を優遇するハンデ戦的な逆転（ボーナス行動やゴール条件緩和）は、対局を長引かせて膠着を再発させるリスクがあり不採用とした。

一斉スライドが目指すのは、**材料的な優劣とは無関係に両者へ平等に与えられ、切るタイミングの読み合いによって終盤まで結果を読み切れなくする**こと。使用は両者に平等な1回ずつだが、「守るものが多い優勢側ほど温存したくなり、失うものが少ない劣勢側ほど早く切りたくなる」という非対称なインセンティブが自然に生まれる点が、ハンデ戦との違いである。

## 2. ルール定義

### 2.1 使用条件

- 各プレイヤーは対局を通じて**1回だけ**使用できる。
- 使用できるのは、自分の駒を移動した後の通常のスライドフェーズ中のみ（＝合法な移動が無くパスするターンや、先手第1ターンのようにそもそもスライドフェーズに入らないターンでは使えない）。
- 1ターンにつき、通常の列スライドと一斉スライドはどちらか一方のみ選べる。

### 2.2 効果

- 盤面の**5行すべて**を、プレイヤーが選んだ**同じ方向（左または右）**へ同時に1マス分スライドさせる。
- 各行の挙動は通常のスライドと同じ（端から押し出された駒はその行の反対側へ独立にラップアラウンドする、駒は取れない）。
- 5行それぞれに別方向を指定できる案も検討したが、UIと理解コストを抑えるため、全行共通の1方向を選ぶ形に簡略化した。

### 2.3 既存のスライド制限との関係

一斉スライドは以下3つの制限をいずれも受けない。

| 制限 | 通常のスライド | 一斉スライド |
|---|---|---|
| 移動連動（今動かした駒の列に限定） | 適用される | 適用されない（全行が対象のため無関係） |
| 巻き戻し禁止（相手の直前のスライドを逆方向に戻せない） | 適用される | 適用されない |
| 空列禁止（駒が無い列は選べない） | 適用される | 適用されない（空の行は見た目上変化しないだけで、選択自体を妨げない） |

一斉スライドの実行後、`_lastSlideRow`（巻き戻し禁止の判定に使う直前スライド記録）は更新しない（`-1`のまま）。全行を一括操作する特殊行動であり、特定の1列を「直前のスライド」として記録する対象ではないため。

### 2.4 コスト（反動）

一斉スライドを使った次の自分の番は、スライドフェーズを行わない（移動のみで手番を終える。合法なスライドが無い場合と同じ扱い）。

### 2.5 勝利判定・定着ルールとの関係

一斉スライド実行直後は、通常のスライドと同様に即座の勝利判定を行わない。スライドでゴールマスに乗った駒は、次にその駒の持ち主のターンが来た時点の「定着」判定（`GameDesign.md`7章）に従う。全滅判定など他の勝利条件への影響はない。

### 2.6 千日手判定との関係

同一局面判定（`RecordPosition`）のキーには、一斉スライドの使用済みフラグ・反動フラグを含めない。これは`_isFirstTurn`・`_movedFromRow`/`_movedToRow`・`_lastSlideRow`/`_lastSlideRight`など、他の補助的なルール状態も同様に判定キーから除外されている既存コードの前例に合わせた意図的な簡略化であり、新規の課題ではない。

## 3. 実装

- `Assets/Scripts/GameManager.cs`
  - `_usedAllInSlide[2]` / `_skipNextSlide[2]`（プレイヤーごとの使用済み・反動フラグ）
  - `OnAllInSlideClicked(bool slideRight)`（一斉スライドの実行）
  - `SlideRow(int row, bool slideRight)`（1行のスライド処理。`OnSlideClicked`と共通化）
  - `ExecuteMove`のスライドフェーズ移行判定に`_skipNextSlide`のチェックを追加
  - `UpdateSlideButtons`で一斉スライドボタンの有効/無効も更新
  - `RestartGame`で両フラグをリセット
- `Assets/Scripts/AllInSlideButton.cs`（新規）: `SlideButton`と同じパターンのUIボタン。`SlideRight`と`SetInteractable`を持つ。
- シーン: `SlidePanel`配下に`AllInSlideLeft`/`AllInSlideRight`ボタンを追加（`SL`/`SR`列ボタンの外側に縦長で配置）。

## 4. 既知のトレードオフ・今後の検証事項

- 一発逆転力は高いが単発の切り札のため、対局を通じて「いつ切るか」という読み合いが新たに生まれる。この駆け引きの深さは実際のプレイテストで検証する。
- 反動（次ターンのスライド不可)の重さは仮決めであり、強すぎる/弱すぎる場合は調整対象とする。
- 5行同一方向という簡略化により、各行を個別に狙う精密なコントロールはできない。プレイテストの結果、行ごとの方向指定が必要と分かればUIごと再設計する。
